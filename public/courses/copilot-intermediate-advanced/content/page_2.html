Estimated time: 7-8 minutes

Goal: Name the parts of an agent and say what each one does to its behaviour.

The NSS agent, opened up

The NSS report from Module 1 has an agent built for it: the Programme Feedback Report agent. Everything the prompt left out (never name staff, keep access needs out of the counts, four themes and no more) is written into it once. Each of those rules sits in a specific part of the agent, and knowing which part is most of the skill of building one.

A Copilot Studio agent has six core parts and two optional ones.

Instructions and skills do most of the work, and they’re the two most often confused.

The finished NSS agent in Copilot Studio, showing its instructions, model, channels, skill, and knowledge sources.

Instructions are the behaviour, skills are the format

Instructions say who the agent is and what it must never do. The NSS agent’s instructions include:

Never name a member of teaching staff, an administrator or a respondent.

Leave Recommendations empty. That section is the programme lead’s.

Skills say how one output is formatted. The NSS agent’s skill sets out the ten report sections in order, the columns of the themes table, and how the flagged comments are laid out. A skill loads when the agent reads its description and decides it applies, so the description decides whether the skill gets used at all.

“Never name staff” passes the test: it holds for any output the agent produces. “Put the four themes in a table with count, summary, and quote” fails it: it belongs to this report. The split also means an agent can gain a second output format, a one-page summary for a committee say, by adding a skill, without touching its “never” rules.

Where a rule goes: in the instructions if it holds whatever the output, in a skill if it shapes one output.

The NSS agent’s reports have the right themes and counts, but the sections come back in a different order from the house template each time. Where does the fix belong?

Knowledge, tools, and grounding

An agent is grounded when its answers come from sources you chose: your documents and your University’s own material, rather than whatever the model knows in general. A grounded answer is about this programme, not about programmes like it.

The NSS agent is grounded in three documents, each with a job:

  • This year’s workbook is the evidence. Every number and quote comes from it.
  • The house template shows what the finished report looks like.
  • Last year’s signed report gives the comparison, and the University’s own wording.

Knowledge and tools can hold the same document in different ways. A file uploaded to knowledge is a copy the agent reads. A tool is a live connection to where the file lives, such as a SharePoint folder. The difference decides what can start the agent: an uploaded copy is replaced by hand, while a tool can pick up the new file the moment it lands.

Knowledge and tools compared: an uploaded copy against a live connection to where the file lives.

With a Microsoft 365 Copilot licence, Copilot is like a capable new starter who’s been given your mail, files, and meetings, and can walk into any room you hold a key to. That’s the New Starter Who’s Read Everything. An agent extends the same idea, and sharing it matters:

  • A SharePoint location connected as knowledge respects each user’s own permissions. A colleague sees only what they could open anyway.
  • A file uploaded to an agent’s knowledge can be read, through the agent, by anyone the agent is shared with, whatever its permissions were in its original location.

Before sharing an agent, check every uploaded knowledge file. If a colleague should not be able to open the file directly, it should not be uploaded to an agent they can use.

The NSS workbook does the same job whether it’s uploaded as knowledge or reached through a SharePoint tool.
