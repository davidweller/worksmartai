Module 6: Build and test the workflow

Estimated time: 7-8 minutes, plus about 20 minutes to build and test

Goal: Build the planned workflow in Copilot Studio, and test it before anyone relies on it.

Before you build

A workflow uses agents that already exist, so both agents come first.

  • Build and test the checker with the Module 4 steps, from its plan in Module 5. It gets no tools and no house template.
  • Publish both agents to your own profile. An agent step can only call a published agent. Publishing isn’t sharing: nobody else can use the agents until they’re shared, and sharing still follows the category from Module 3.
  • Set up test folders, a test Responses folder and a test Reports folder, and send every email to yourself while you test.
  • Keep the dummy files small. Every agent step uses Copilot Credits each time it runs.

Build it: From plan to Copilot Studio

Workflows are built in the same place as the agents. Build in the order of the plan, one step at a time.

  1. Open Copilot Studio, go to Workflows in the left sidebar, and choose New workflow. Name it after the job, such as NSS Feedback Report Cycle. It builds on the same GitHub Copilot harness as the agents from Module 4.
  2. Set the trigger on the Start step. Choose the SharePoint trigger for a new file in a folder, and point it at the test Responses folder, not the live one.
  3. Add an action to get the file’s content. Add a Connector step for SharePoint that gets the content of the file from the trigger.
  4. Add the drafting agent step. Add an Agent step, choose the Programme Feedback Report agent, and write the message it receives. Insert the file content as dynamic content, so each run works on the file that started it.
  • The NSS workflow in the Copilot Studio designer, with the drafting agent step selected.
  1. Add the checking agent step. Add a second Agent step for the Programme Feedback Report Checker. Pass in the draft from step 4 and the file content from step 3, and nothing else.
  2. Add the condition. Add an If/Else step that looks for mismatched or untraceable rows in the claims register, and puts any it finds first in the review message. Both branches go on to the review.
  3. Add the human review. Assign it to one named person: the programme lead in use, and yourself while testing. Collect a yes or no for the decision, and a text input for the Recommendations section.
  4. Add an If/Else on the decision. If approved: save the report and the claims register side by side in the Reports folder, email the report to the circulation list, and email the accessibility section to the Disability and Inclusion Service. If rejected: nothing is filed or sent.
  5. Test each step as you add it, with a dummy file dropped into the test Responses folder, before running the whole workflow.

Copilot Studio’s workflow designer is changing quickly. If a step name here doesn’t match what you see, use the step that does the same job.

Two alternatives sit alongside New workflow:

  • New agent flow, on the same Workflows page, builds on the standard harness. It’s free to build and test, and uses credits only once published. It works with standard-harness agents, so an agent from Module 4 would need rebuilding on that harness to be used in one.
  • Power Automate cloud flows handle the actions and approvals without the agent steps, for jobs that need no language work.

Your turn: Build your planned workflow in Copilot Studio, on test folders and dummy files. Start with the trigger and the first agent step, test them with a dummy file, then add the rest one step at a time. Run your test set before anyone relies on the output.
