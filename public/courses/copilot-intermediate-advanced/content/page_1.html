Estimated time: 9-10 minutes

Goal: Tell the difference between a prompt, an agent, and a workflow.

The job that needs explaining every time

Imagine someone pasted a programme’s National Student Survey comments into Copilot and explained what they wanted: a report that condensed the comments into four themes to use, a rule about never naming staff, and what to do with a comment about a student’s accessibility needs. The summary was useful. You'd like to do the same task, and it would be useful if you could just click a button (and start an agent), rather than try to find the old prompt or start again. Now you have access to Copilot Premium, you can!

Before and after: explaining the NSS job every summer, compared with writing the rules down once.

What this changes

Jobs worth moving from a prompt to an agent share three things:

  1. They come round on a cycle,
  2. They draw on the same sources each time,
  3. The rules for doing them well don’t change.

The NSS report has all three: it comes round every summer, it draws on the same response file, house template, and last year’s report, and its rules don’t change from one year to the next. The examples below, grouped by role, share that shape. The last one under planning and analytics is the NSS report itself.

Possibilities for agents

Here are some ideas for agents that could be useful for you:

If you deliver projects and programmes:

  • Track the actions from each week’s project meeting: what’s open, what’s overdue, and what’s closed since last week.
  • Draft a new project’s scope, milestones, and dependencies from the approved business case, with every line citing its paragraph.
  • Turn a month of project updates into the highlight report, in the same shape every time.

If you manage the portfolio or administer projects:

  • Pull the same fields from every project’s return into one portfolio view.
  • Check each submission against the template before it reaches a board, and list what’s missing.
  • Draft the covering note for a meeting pack from the papers already in the folder.

If you work in planning and analytics:

  • Give the week’s admissions position against target and against the same point last cycle.
  • Run the same check on every faculty planning submission against the planning guidance.
  • Theme a survey’s free text against a fixed framework, so this year can be compared with last.

Time saved is the smaller gain. The larger one is consistency: the job is done the same way whoever runs it and whichever week it is, so the time spent goes on the part that needs judgement, such as what the overdue actions mean and what to do about them.

First run: The NSS report as a prompt

This is the job that runs through the course. A programme’s National Student Survey results have arrived, and a report is needed on what students said. The university, Calderbrook, is fictional, and every name, figure, and comment in the file is invented.

Attach the workbook and paste in the prompt below. It gives Copilot three things: the role to take, the context it needs, and the task.

You’re a student surveys analyst at a UK university. The attached workbook holds one programme’s National Student Survey responses, with scored questions and a free-text column. Theme the free-text comments against four themes and no others: teaching and learning, assessment and feedback, organisation and management, and learning resources. For each theme, give the number of responses, a one-line summary, and one comment quoted word for word. Put the four themes in a table.

The structured prompt for the NSS report in Copilot, with the workbook attached.

The result should be a table with four rows, counts, and quotes. Check it against three points:

  • Does any quote name a member of staff? Four comments in the file do.
  • Has a student’s comment about their learning support plan been counted as a learning resources complaint, or summarised into a line?
  • Has a fifth theme appeared, such as student voice?

The prompt didn’t include the rules that make this report safe to circulate: never name staff, keep access needs out of the counts, four themes and no more. Each would need adding to the prompt, and adding again on every run, by anyone who runs it. An agent holds those rules once.

Think of one job you do on a cycle, weekly or monthly basis, where you explain the same thing to Copilot each time. Write your answers to these three questions: What’s the job, and what do you have to explain every time you run it? Which files or folders does it always draw on? Is there anything it must never do, and have you ever had to correct it for doing it?

Three ways to do the same job

Each definition comes with a quick test.

A prompt is an instruction you type once and read the answer to yourself. You supply the context every time: the document, the background, what good looks like. The test: if you closed the window, it’s gone.

An agent is “a job you’ve written down, with sources attached, so you can run it again without re-explaining.” Same instructions, same documents, whoever runs it. The test: someone else on your team can run it and get the same shape of answer.

A workflow is “a job that you’ve broken into steps and linked together. Those steps can be people, agents, or automations.” Something starts it, such as a file arriving or a set time, so nobody has to remember to. The test: it has a step that isn’t an agent, such as a person approving, a branch, or a file landing somewhere.
